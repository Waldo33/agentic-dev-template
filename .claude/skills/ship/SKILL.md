# Выкатка

## Перед push

1. `pnpm check` зелёный (или хотя бы `pnpm check:fast` + `pnpm --filter <app> build` для правок одного приложения).
2. Правил UI — e2e против локального сервера, посмотри скриншоты сам (`apps/<app>/test-results/**/*.png`).
3. Diff больше пары файлов или трогает данные, деньги, авторизацию — субагент `reviewer`. Чини только то, что влияет на корректность и требования.
4. Есть миграция — она расширяющая, проверена на локальной базе, есть совместимость со старым кодом.
5. `git status` — в коммите нет скриншотов, `.env`, `test-results`, временных файлов.

## Коммит и push

```bash
git add -A && git commit -m "<что изменилось для пользователя>" -m "<зачем и как>"
git push origin main
```

## Наблюдение

```bash
gh run list --branch main -L 1
gh run watch <id> --exit-status
```

Пайплайн: plan → check → build+e2e (по затронутым приложениям) → deploy → verify → (rollback) → notify. Красное:

| Шаг | Что делать |
|---|---|
| check | `gh run view <id> --log-failed`, воспроизведи локально `pnpm check`, чини |
| e2e | `gh run download <id> -n e2e-<app>` → скриншоты и трейс Playwright; чини, добавь проверку |
| deploy | обычно доступ/секреты/сервер: `gh run view --log-failed`; `ops.yml -f action=status` |
| verify (откатили) | прод уже на прошлой версии. Смотри логи нового контейнера: `ops.yml -f action=logs -f app=<app>`, ошибки — `errors-recent`. Чини следующим коммитом |

Не оставляй `main` красным: если починка дольше 15 минут — `git revert` и разбирайся спокойно.

## После

- Отметь `passes` в `features.json`, запись в `PROGRESS.md`.
- Отчёт владельцу: что изменилось для пользователя, ссылка, скриншот, флаги, «переоткрой вкладку».
