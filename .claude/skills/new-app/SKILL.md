# Новая идея → живой адрес

Цель: за один заход владелец получает `https://<имя>.<домен>` с рабочим ключевым сценарием, ошибками в Bugsink, событиями в аналитике, флагом на рискованное и проверкой в Gatus. Ничего не настраивая сам.

## 1. Интервью (одно сообщение, до 4 вопросов)

Спроси только то, без чего нельзя сделать первую версию, кнопками (AskUserQuestion): для кого, ключевое действие (что считать успехом), что точно не делаем, нужен ли вход/оплата. Не ответил за разумное время или сказал «на твоё усмотрение» — бери самое простое и пиши, что выбрал.

## 2. SPEC.md и features.json

```bash
pnpm new-app <имя>      # латиница, 2–30 символов; имя = поддомен
pnpm install
```

Заполни `apps/<имя>/SPEC.md`: зачем, ключевое действие (`activation`), в рамках / вне рамок, сквозной сценарий, метрики. В `features.json` — 3–8 проверяемых фич первой версии, все `passes: false`. Обнови `AGENTS.md` приложения (одна строка «что это»).

## 3. Код

- Одна фича за раз, по `features.json`. На каждую — шаг в `e2e/` (телефон в приоритете).
- События: добавь свои в `src/lib/events.ts`, вызови `track()` на ключевом действии (`activation`).
- Рискованное или незаконченное — `release_*` флаг в `src/lib/flags.ts`, по умолчанию `false`.
- Таблицы — новой миграцией `migrations/000N_*.sql` (только расширяющей).
- Убери из шаблона то, что не нужно идее (счётчик визитов, кнопку `hello_click`), — вместе с событием в каталоге.

## 4. Проверка

```bash
pnpm check
pnpm --filter <имя> build && (cd apps/<имя> && node .next/standalone/apps/<имя>/server.js) &   # или dev
BASE_URL=http://localhost:3000 pnpm --filter <имя> e2e
```

Субагент `qa` проходит фичи из `features.json` как пользователь на телефоне; субагент `reviewer` смотрит diff против `SPEC.md`. Только после этого `passes: true`.

## 5. Выкатка

Скилл `ship`. База, env-файл и проверка в Gatus для нового приложения создаются шагом `prepare` пайплайна автоматически (Ansible, роль `app_env` читает список `apps/*`). Первый деплой выпускает сертификат Let's Encrypt — до минуты.

## 6. Флаги и дашборд

- Флаги: в репозитории флагов создай `<имя>/features.yaml` (образец — `infra/flags-repo/example/features.yaml`), namespace = имя приложения. Включи `release_*` для сегмента владельца, если он есть, иначе оставь выключенным и скажи, как включить в панели.
- Дашборд Grafana общий: «Приложения» с выбором `app` — новое приложение появится в нём само после первых событий.

## 7. Отчёт владельцу

3–6 строк: что умеет первая версия, ссылка, скриншот с телефона, что проверить руками, какие флаги выключены и как их включить, какую метрику смотреть через неделю. Запись в `PROGRESS.md`.
