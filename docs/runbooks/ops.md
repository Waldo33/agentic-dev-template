# ops.yml — операции на проде

Как запустить:

- **агент** (облачная сессия): `scripts/ops.sh <действие> [приложение|-] [аргумент]` — создаёт issue `ops: <действие> [приложение]`, аргумент кладёт в текст issue, ждёт ответный комментарий и печатает его;
- **владелец**: issue с таким же заголовком (длинный аргумент — в текст) или Actions › ops › Run workflow.

Выполняются только issue от владельца и соавторов репозитория. Ответ — комментарием, issue закрывается.

| Действие | Приложение | Аргумент | Что делает |
|---|---|---|---|
| `status` | — | — | uptime, диск, память, контейнеры, таймер бэкапа на обоих серверах |
| `logs` | да | строк (200) | логи запущенного контейнера приложения |
| `restart` | да | — | `docker restart` контейнера, потом `/up` |
| `rollback` | да | sha | `kamal rollback <sha>` (последние 5 версий хранятся на сервере) |
| `sql-readonly` | да | SQL | запрос к базе приложения под ролью `<имя>_ro` (только чтение) |
| `clickhouse-query` | — | SQL | запрос к ClickHouse под `reader`, лимит 30 с |
| `backup-now` | — | — | внеочередной бэкап обоих серверов |
| `set-sentry-dsn` | да | DSN | DSN проекта Bugsink для приложения (применится при деплое) |
| `dns-check` | — | — | куда смотрят поддомены приложений и панелей |
| `test-alert` | — | — | пробное сообщение в Telegram |
| `send-panel-passwords` | — | — | пароли Grafana, Bugsink, Flipt — владельцу в Telegram |
| `redeploy` | — | — | `pipeline` на всех приложениях |
| `provision` | — | `bootstrap` или теги | `provision` (Ansible): полностью, первый прогон под root или только теги |

Произвольных команд нет специально. Нужна новая операция — добавь действие в `ops.yml` с проверкой ввода и строку сюда.
